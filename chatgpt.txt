4. НОВАЯ СИСТЕМА ПРИВЯЗКИ TIKTOK И НАЧИСЛЕНИЯ БАЛЛОВ (ТЕКУЩАЯ ЗАДАЧА)
Пользователь хочет заменить старую ручную систему заявок на баллы автоматической.

Требуемый пользовательский сценарий:
A. Привязка аккаунта
1. Участник запускает Discord slash-команду /привязать_аккаунт и передаёт ссылку на TikTok-профиль.
2. Бот генерирует случайный код из 5 символов.
3. Участник добавляет код в описание (bio) своего TikTok-профиля.
4. Бот показывает кнопку «Проверить».
5. При нажатии бот проверяет bio через официальный TikTok API.
6. Если код найден в профиле — привязка успешна, сохранить Discord user ID, TikTok username/profile URL и нужные идентификаторы в SQLite.
7. Если кода нет или он не совпадает — сообщить, что привязка не прошла, предложить проверить код и повторить.
8. После успешной привязки показывать TikTok-ссылку в профиле/данных участника в формате ссылки на @username (например, «TikTok: https://www.tiktok.com/@username»).

B. Отправка видео и начисление
1. Участник отправляет ссылку на TikTok-видео в предназначенный личный канал/место отправки.
2. Если аккаунт не привязан — отклонить отправку и попросить выполнить /привязать_аккаунт.
3. Если аккаунт привязан — через TikTok API проверить, что ролик принадлежит именно привязанному аккаунту.
4. Получить количество просмотров (view_count).
5. Начислять 1 балл за каждые 5 просмотров: целочисленно views // 5.
6. Сохранять уникальный video ID, чтобы нельзя было получить баллы повторно за одно и то же видео.
7. Сохранять привязку и историю начислений в SQLite, переживающую перезапуски бота.

- Старый формат сообщения просил никнейм Minecraft, ссылку на видео и количество/заявку на баллы.

D. Важное ограничение API
- Нельзя обещать, что бот может надёжно проверить bio или просмотры простым открытием публичной ссылки TikTok.
- Для надёжной проверки нужна авторизация владельца через TikTok Login Kit и официальные разрешения.
- Display API выдаёт профиль и список видео авторизованного пользователя в рамках доступных scopes. Проверить актуальные требования и review status scopes в Developer Portal до реализации.
- Проверка видео должна сопоставлять owner/username или список video IDs авторизованного пользователя, а не полагаться на введённый URL.
- Нужно предусмотреть API rate limits, истечение/обновление access token, ошибки приватности/недоступного видео, задержку обновления view_count и повторную проверку просмотров, если начисление должно учитывать рост просмотров после первой отправки.
- Уточнить бизнес-правило: начислять один раз по просмотрам на момент отправки или делать периодические доначисления при росте просмотров. Пока пользователь описал отправку ссылки и начисление по текущим просмотрам; повторное начисление за один ролик запрещено по умолчанию.
